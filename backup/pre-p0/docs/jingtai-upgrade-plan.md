# 景泰小学周边2公里：建筑缺失说明与优化升级方案

日期：2026-09-22  
状态：原因已核查；以下升级均为待实施方案，本轮未修改功能或数据。

## 一、为什么学校附近像没有建筑

**主要原因是现有建筑数据在校园近处缺失，不是整张地图加载失败。现有显示策略和高度缺失，又让这种空白更明显。**

1. **有校园边界，不等于有教学楼轮廓。** 当前正确校园是景泰小学（景泰校区）、云龙路38号，OSM `way/1178149399`；数据只有校园用地边界，不能把整个黄色校园面直接拉伸成教学楼。
2. **建筑数据集中在外围，近处明显不足。** 全部2公里有906个建筑/部件要素，但以校园中心计算，100米内为0，200米内仅2个，最近轮廓约158米。原始数据和转换结果在近场一致，不是程序转换时把学校周边楼房批量删了。
3. **范围内只显示本地快照的三维建筑。** 为避免与底图重复叠楼，程序关闭2公里内的底图三维楼块，保留底图二维建筑轮廓，再叠加本地快照。这个策略不能补偿快照没有覆盖的建筑。
4. **绝大多数已收录建筑也没有高度。** 906个要素中897个高度未知，在普通模式统一用9.6米示意，容易呈现成低矮块；只有4个有OSM高度标注、5个可按层数换算。高度标注不等于实测。
5. **验收存在缺口。** 之前的测试确认了已有建筑能显示、搜索与交互可用，却没有证明校园近场与真实街区的建筑覆盖一致。“906个要素”和“测试通过”不能作为“附近建筑齐全”的证据。

不能把数据中的空白解释成现实中的空地，也不能为了填满画面而生成虚构楼房。

## 三、升级目标与不变范围

目标不是增加更多按钮，而是先让校园附近的真实街区能够被识别，再改善三维层次和加载可靠性。

- 同一项目保留广州塔3公里、景泰小学2公里，学校中心和校区身份不变。
- 先检查校园及周边500米，重点是校园内部、云龙路沿线、校园西侧和南侧空白街区，再检查完整2公里。
- 轮廓、名称、楼层、高度分别记录来源，允许某个字段缺失，不把一个字段可靠当作整栋信息可靠。
- 不接收费API，不做生成式三维重建，不随机补楼，不凭照片猜高度，不把直线距离冒充步行距离。
- 新增外部数据必须先确认本区域覆盖、坐标系、使用和再分发许可；免费浏览不等于允许抓取、描摹或再分发。
- 校园用地、教学楼、运动场、山地边界和地形高程保持独立，不互相冒充。

## 四、分阶段实施方案

### P0：先建立校园近场覆盖基准

**目的：明确缺哪些楼、缺在哪一层，而不是再次用总数量过关。**

1. 建立100、200、300、500米及2公里分区审计，统计原始要素、有效几何、最终要素、剔除原因和来源。
2. 将每个已核验建筑分为四类：原始来源不存在、原始存在但转换丢失、产物存在但未显示、已显示但视觉辨识不足。
3. 通过有合法使用权限的参考资料建立校园近场建筑核对清单，记录位置、来源、核验日期和待确认项。独立参考不足时明确“尚不能评估覆盖率”，不能把当前OSM自己当作完整真值。
4. 修正半径边界判定：采用建筑几何与2公里圆相交规则，处理跨界楼、包含中心的大面和洞；同一规则用于生成、报告与测试。
5. 保留现有原始文件及校验和；所有候选数据先生成独立候选版本，不直接覆盖现有可用快照。

交付物：近场缺失清单、来源/剔除报告、同镜头基线截图、可复现的生成和检查过程。

验收：每处已确认缺楼都有分类和证据；刻意移除一个核验建筑、制造一个错误半径剔除时，对应检查必须失败；单纯增加外围建筑数量不能使检查通过。

### P1：补齐有来源的建筑轮廓

**这是解决“学校附近没楼”的核心阶段；P0确认来源后才能实施。**

按以下顺序推进，而不是并行堆叠多个未经核实的数据源：

1. 核对最新OSM与现有快照的差异。若数据本身没有新增，明确记录无改善，不把反复请求当作补全。
2. 检查当前底图与本地快照是否存在真正互补的轮廓；不能预设底图更完整，也不能直接依赖瓦片内部ID与OSM身份一一对应。
3. 如同源数据仍缺，评估具有明确开放许可的官方或社区建筑矢量数据。来源未通过覆盖、许可、坐标系检查前，不承诺接入成功。
4. 若只能使用用户提供或有合法描摹权限的资料，先单独确认录入范围及授权，再核验轮廓；不从商业地图截图自行描摹并声称为OSM数据。
5. 融合时对已核实身份、几何重叠、建筑外壳/部件和跨瓦片重复分别处理；歧义项保留待核验，不用名称相同或距离接近直接合并。
6. 生成统一的可交互建筑数据和索引，保证显示、点击、搜索、分享及统计使用同一来源身份。校园教学楼只有取得真实轮廓才进入建筑数据。

每个补充要素至少记录：来源名称、原始身份、来源时间、许可、坐标系及转换说明、轮廓依据、高度依据、核验状态。不能给非OSM要素伪造OSM链接；混合许可是否允许合并再分发需在接入前确认。

验收：近场核验清单中的每栋已确认建筑都有显示结果或明确阻塞原因；不存在双楼重叠、校园用地整块拉高、洞被填实、未知名称或高度被编造的情况。没有可靠新增来源时，本阶段保持阻塞，不以视觉填充交付。

### P2：调整三维表达和首屏构图

**解决“已有建筑仍像矮块”，不能替代P1的数据补全。**

1. 保留高度三类语义：OSM高度标注、层数换算、未知。先补可核验楼层/高度，再调整显示，不统一把未知建筑抬高到20米或30米。
2. 普通模式的未知建筑允许保持明确标注的示意高度；高度透视镜继续使用平面且不参与数值高度分档。
3. 在真实轮廓恢复后再调整近场配色、明暗层次、相机和校名位置，让校园周边楼群、道路及山脚关系清晰，不通过移镜头绕开缺失区。
4. 校园暖黄表示用地，教学楼与运动场有数据后分别表现；不把暖黄底板当成校园建筑模型。
5. 仅在已确认底图存在互补建筑、且完成去重和许可核查后，才考虑补充背景楼层；缺少来源身份的背景不得伪装成可查询建筑或混入高度统计。
6. 数据显著增多后再评估空间分块和按需加载；性能优化不能重新把近场小楼批量过滤掉。

验收：同一镜头、同一尺寸对比升级前后；近场核验建筑仍完整，三档氛围都能辨认；未知高度说明可见；搜索定位、选中高亮、来源卡和分享指向同一个要素。

### P3：提升加载可靠性和失败提示

既有回归记录显示，OpenFreeMap样式请求曾出现 `net::ERR_CONNECTION_CLOSED`，导致入口保持禁用；这与本次“页面正常但近场缺楼”是不同问题。

1. 区分底图样式失败、本地建筑失败、校园数据失败和局部瓦片失败，提示具体影响及可操作的重试方式。
2. 对可重试的连接故障使用有限次数、退避的重试；429不连续轰炸，失败重试不重复创建地图、事件或定时器。
3. 评估在许可允许下固定并缓存地图样式及合法资源，同时保留来源署名；缓存样式不等于离线拥有全部瓦片、字体和图标。
4. 是否提供“仅本地建筑”降级视图单独决策；若实施，必须明确标注底图未加载，不能把缺道路的降级画面当完整场景。

验收：分别注入样式断连、超时、本地快照503和局部瓦片失败，检查提示、重试、恢复及资源释放；不得通过延长测试超时或隐藏错误来算成功。

### P4：校园细节、步行距离与山地升级

这些能力保持数据前置，不抢占近场补楼工作。

| 项目 | 必要前提 | 无数据时的处理 |
| --- | --- | --- |
| 校园教学楼 | 可核验且许可明确的轮廓；高度另行核验 | 不把校园用地当教学楼 |
| 红绿运动场 | 真实校内pitch/track轮廓及位置证据 | 保留缺失说明，不画装饰跑道 |
| 地铁步行距离 | 可核验校门、可步行连接、具体车站入口及通行规则 | 继续单列直线距离，步行暂缺 |
| 白云山起伏 | 有许可的DEM及坐标/高程基准，完成楼块贴地与性能验证 | 继续仅显示林地范围 |

真实步行距离不能通过最近道路吸附跨墙生成；DEM只能表现地形，不能补建筑或测出教学楼高度。运动场和步行距离的原有未满足验收，在拿到真实数据并通过检查前不得删除或改成通过。

## 五、验收升级：不再只看数量和测试通过率

1. **覆盖验收**：对独立核验清单逐项比对；完整2公里检查不能替代校园近场检查。
2. **链路验收**：为核验要素记录“原始→转换→加载→绘制→点击→卡片/分享”结果，直接定位丢失环节。
3. **真实性验收**：任何轮廓、身份和高度都可追溯；对虚构高度、错误坐标、校园错误拉伸、重复建筑分别注入缺陷，确认测试能拒绝。
4. **视觉验收**：固定首屏、校园近景和2公里总览；覆盖桌面1440×960以及390×844、320×568、568×320等小屏，检查校名、建筑、来源卡及署名，不以相机避开缺失区。
5. **回归验收**：保留广州塔场景、三档氛围、用途/高度筛选、搜索分享、导览、地点缓存与逐层关闭；不得改动建筑卡片“不遮本楼”的既有规则来换取通过。
6. **性能验收**：新增数据后在同一设备和镜头复测加载耗时、交互响应、连续渲染及五分钟操作，区分动画回调与GPU性能，不凭两次堆快照宣称无泄漏。
7. **结果口径**：区分首次通过、失败后复跑通过、数据阻塞和未测；外部服务故障记录请求证据，不把所有超时都归为网络。
